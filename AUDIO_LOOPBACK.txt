EC20 Toolbox — unified HTTPS audio integration 1.4.0 / audio backend 0.2.0
============================================================================

Canonical entry: https://192.0.2.10:8788/
Audio page:      https://192.0.2.10:8788/#audio
One console login, one Secure/HttpOnly/SameSite=Strict __Host-ec20_session cookie.
The existing admin password, TLS leaf certificate and client trust are retained.
Old console/audio sessions require one fresh login after the upgrade.

Architecture
------------
Browser -- HTTPS8788 --> ec20-console (login, CSRF, application UI)
                            | authenticated fixed HTTP control calls
                            v
                    127.0.0.1:8790 ec20-audio-loopback (separate process)
Browser <-------- VPN UDP8789 / DTLS-SRTP --------> audio backend

The browser never receives the private gateway key. Both services load that key
through systemd LoadCredential. The audio service does not read the admin password
or TLS private key. It retains DynamicUser, PrivateDevices, no capabilities,
read-only filesystem and no AF_UNIX/system-D-Bus access.
The main console receives TLS credentials through systemd; original files stay
root-private and unchanged. No certificate replacement or insecure TLS bypass.

The gateway accepts only fixed routes and a literal loopback upstream. It ignores
client identity headers and forwards only authenticated console owner/expiry.
Internal requests require a private key and a loopback peer. Old identity headers,
expired/revoked sessions, wrong Origin, missing CSRF and oversized SDP are rejected.
Logout revokes the owner and releases audio, including offers still being created.
An unavailable audio backend returns503 only for audio; console/network work stays
independent. Page navigation stops capture; normal 5-second console polling keeps
the media DOM mounted. Refresh can discover/release a prior owned media slot.

Compatibility
-------------
http://192.0.2.10:8787/ redirects GET/HEAD to canonical HTTPS, preserving path/query
and the browser's original fragment. Plaintext mutations receive426; refresh the
old page instead of posting credentials or actions through HTTP.
The former https://192.0.2.10:8788/ audio bookmark opens the unified console;
choose Audio Lab in the sidebar. /audio, /audio/, /audio-lab redirect to /#audio.
Legacy /api/loopback and /api/loopback/stop aliases continue under console auth.
The old __Host-ec20_audio_session cookie is ignored; there is no second login.
UDP8789 is still needed for media; it is not a second web UI entry point.

Operation
---------
440Hz tone: no microphone permission required, server round trip analysed,20s max.
Microphone echo: use headphones, grant existing site microphone permission.
Every session: at most3min, no media30s -> release, one slot, owner-scoped stop.
Mute/volume affect returned playback. No recording or audio persistence.
This is browser<->69 software echo, NOT EC20 cellular call audio. No ALSA, serial,
modem commands, module reset, routing changes or raw AT are involved.
Main login is8h. Audio expiry is bounded by that session and the3min media limit.
Main console restart invalidates its sessions; any orphan media expires within
its existing timeout. Re-login and retry after release; no automatic mic start.

Build and deployment
--------------------
make test; make build; make build-audio
Build probe: go build -o bin/ec20-audio-probe ./cmd/ec20-audio-probe
Upload binaries, both units and deploy/unify-web.py together to a staging directory.
Run sudo python3 unify-web.py --check-only, then sudo python3 unify-web.py.
This migration is for the existing69 installation and retains a dated private
backup. It refuses duplicate backup/occupied internal port or active media/calls.
It updates/restarts only ec20-console and ec20-audio-loopback, with a10min timer.
Verify first, then stop ec20-web-unify-rollback.timer.
Rollback: sudo python3 /var/lib/ec20-console/backups/https-unified-20261107/rollback.py --rollback
Rollback restores old web units/binaries and ports, retains all data/TLS files,
and does not restart failover, NetworkManager, ModemManager or VPN services.
The old install-audio.py is a legacy standalone installer; do not use it with the
new gateway unit. Integrated upgrades use unify-web.py and then controlled web
release changes retaining the two-service sandbox.

Synthetic live verification
---------------------------
ssh -i ~/.ssh/example.pem operator@192.0.2.10 'sudo cat /etc/ec20-console/credentials.json' |
  bin/ec20-audio-probe -cert server.crt
Credentials are read from stdin only. The probe trusts the explicit public cert,
logs into the unified console, uses the compatible signalling routes, requires
70/80 identical PCMU payload returns, stops and logs out. No microphone or EC20.
