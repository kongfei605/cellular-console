一、重启与中断边界
[ ] GNSS 页面只读观察：不重启 EC20，不暂停 ModemManager。
[ ] GNSS 天线核对、按板卡规范调整位置：不需要为软件配置重启。
    若接头作业必须断电，按板卡要求处理，并纳入 EC20 维护窗口；不要自行带电拆装微型射频接头。
[ ] ec20-uac-ready / sysfs / ALSA 能力只读检查：不重启 EC20。
[ ] 查询 USB/UAC AT 能力：查询本身不要求模块重启；现有 MM 占用 AT 口，
    可能要短暂停止并恢复 ModemManager，期间蜂窝备用可能中断。
[ ] USB 组合的 UAC 功能位由 0 改为 1：需要重启 EC20 / 重新枚举；蜂窝备用暂不可用。
[ ] QPCMV=1,2 选择真实 UAC 音频：即时生效，不要求模块重启；重启后要重新核实路由。
[ ] 浏览器 WebRTC 回环、真实通话测试：不以重启为常规步骤。
[ ] 将 USB 组合恢复原元组：需要再次重启 EC20 / 重新枚举。
[ ] 重启/断电范围仅限 EC20；不重启 69，不操作其有线接口，不重启整个网络栈。

二、开始前保护 SSH 与自动备用（任一不满足就只做只读检查）
[ ] 现场人员在机器旁，能辨认 EC20 原 USB 口、GNSS/GPS、MAIN/DIV 天线口。
[ ] 确认可从 69 的本地屏幕/键盘或独立管理通道操作；不能只依赖 VPN SSH。
[ ] 69 的有线连接和上游稳定，周末网络调试暂时停止；有线故障时不做 UAC 维护。
[ ] /run/ec20-failover/status.json 更新时间新鲜，active=wired、wired_healthy=true、
    cellular_present=true、cellular_healthy=true，tun0/tun1/tun2 全部正常。
[ ] 保留原 SSH 会话，另开一条持续心跳会话；记录 SSH 实际经哪个 VPN/出口抵达。

[ ] 记录当天 PPP PID、ifindex/IP、USB 物理路径/devnum、MM/NetworkManager/主备/VPN PID、
    默认路由、服务版本、USB 完整配置元组；不要硬套之前的 IP、PID 或 tty 编号。
[ ] 备份主备/NetworkManager 配置、服务单元、EC20 原 USB 元组和本次维护记录；权限 root-only。
[ ] 关闭短信自动转发；确认没有短信发送、通话、浏览器音频会话及其他模块配置作业。
[ ] 主备控制器继续运行，保留 EC20 缺席时暂停重拨、插回后恢复、VPN 重连和有线回切策略。

四、UAC 预检查（不重启）
[ ] 先通过 #audio 验证现有软件回环，佩戴耳机；完成后停止，释放回环会话。
    软件回环通过不等于 EC20 真实通话音频通过。
[ ] 在 69 运行已有只读检查：
    先把当天核对过的 ec20-uac-ready 探针放到 69，再运行（不是主控制台二进制）：
    ./ec20-uac-ready-linux-amd64 -usb-path 1-2
    USB 物理路径以当天核对结果为准。退出码 2 表示未就绪，不能改选主板默认声卡代替。
[ ] 必要时使用已审阅的 /usr/local/libexec/ec20-check-uac.py 做只读 preflight。
    --allow-mm-reconnect 是维护动作，必须在有线稳定、现场可恢复、恢复定时器布防后执行。
    它只查询，不会启用 UAC。现有脚本有独立 90 秒 MM 恢复任务，先核对其预算和版本。
[ ] 重新读取并保存完整 usbcfg 元组及 QPCMV/QDAI 能力；不要使用运行中 PPP 的 AT 口或抢占 MM 串口。
    之前记录过 0x2C7C,0x0125,1,1,1,1,1,0,0，仅供对照，不代表周一仍相同。

[ ] 重新读取 GNSS 开关；模块/MM 重启后可能恢复关闭。先恢复备用健康，再在定位页手动启用并验收新鲜定位数据。
[ ] 确认自动备用恢复后，再取消相应恢复定时器；没有恢复就保持现场接管，先救连接。

六、声卡与真实通话音频（不需要再重启模块）

[ ] 协调 AT 所有权后设置/核实 QPCMV=1,2；该路由即时生效、不持久，模块重启后重新核对。
[ ] 当前仓库只有真实 PCM 适配器和保护库，尚未接入线上真实音频 API/UI。
    必须先完成受限声卡权限、只读 D-Bus、真实模式接线和呼叫 ID 绑定，不能把软件回环切个标题就算上线。
[ ] 不授予所有声卡或任意设备权限；音频服务与控制台、主备控制器继续隔离。
[ ] 使用本次再次确认有接听人的授权号码（之前授权测试号码 +12025550123，现场开始前确认仍方便）。

七、有线故障、回切与失败恢复
[ ] 先结束所有电话并停止音频；短信转发保持关闭，恢复有线稳定基线。
[ ] 有线故障测试只能在现场本地控制可用、EC20 备用已健康、自动回滚与恢复职责明确时做。
    使用有界、可自动恢复的链路测试方式；若需物理拔线，由现场按约定立即插回，不能指望远程脚本恢复拔掉的线。
[ ] 观察有线失效→EC20 接管→VPN 重连→SSH 能否重新连接；已有 TCP SSH 会话不保证无缝保留。
[ ] 恢复有线，观察稳定期结束后自动回切、VPN/SSH 恢复；EC20 消失且有线健康时应立即回切。
[ ] 任一失败：先恢复有线和本地 SSH/VPN，再恢复 MM runtime mask/原服务，再恢复蜂窝连接。
[ ] 若 USB/UAC 配置导致异常：现场使用仍可用的管理口，按本次备份原元组回退，并再次重启 EC20。
    若 AT 端口不可用，停止盲目尝试，按板卡厂商恢复流程现场处理；自动回滚不能保证救回坏端口组合。
[ ] 确认系统最终回到有线主用、EC20 健康备用、3 VPN 健康，临时 mask/测试进程/定时器已处理。
[ ] 记录最终 USB 元组、GNSS 状态、UAC/通话结论与回滚位置；短信转发按需求单独配置并启用。
